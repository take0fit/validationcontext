# Implementation Plan

- [x] 1. 検証エラーモデルの一貫性を高める
- [x] 1.1 エラー収集時のメッセージ規約を統一する
  - すべての検証結果がフィールド名・理由・補足情報の同一フォーマットで扱えるようにする
  - 既定メッセージとカスタムメッセージの優先順を明確化し、空メッセージ時の挙動を安定化する
  - _Requirements: 1.1, 1.4, 2.1, 3.4_
- [x] 1.2 スタックトレース採取のコストと可読性を改善する
  - エラー件数増加時に過剰なメモリ消費を起こさないよう採取戦略を整理する
  - 集約エラーの表示で開発者が原因箇所を追いやすい順序にそろえる
  - _Requirements: 1.1, 1.4_
- [x] 1.3 集約エラー生成の契約を強化する
  - エラーなし時とエラーあり時で戻り値の意味を明確化し、呼び出し側の分岐を簡潔にする
  - 複数エラー時のメッセージ連結ルールを安定化し、将来拡張しやすい形にする
  - _Requirements: 1.3, 1.4, 1.5_

- [x] 2. 検証ルール実装の重複を削減する
- [x] 2.1 (P) 文字列系バリデーションの共通化
  - 形式検証と文字種検証で共通の失敗ハンドリングを使い回せるよう整理する
  - 正規表現ベースと rune 判定ベースの役割を整理し、重複ロジックを最小化する
  - _Requirements: 2.1, 2.2_
- [x] 2.2 (P) 数値・日時・ネットワーク系バリデーションの共通化
  - 範囲検証と形式検証の分岐パターンを統一し、追加ルール実装時の差分を減らす
  - エラーメッセージ生成の規約を統一して利用者の予測可能性を上げる
  - _Requirements: 2.3, 2.4_
- [x] 2.3 (P) ファイル検証の境界条件を整理する
  - ファイル未存在・情報取得失敗・拡張子不一致・サイズ超過を区別して扱えるようにする
  - 実行環境依存エラーの扱いを標準化して、利用者側の復旧判断をしやすくする
  - _Requirements: 2.5_
- [x] 2.4 必須入力判定の責務を明確化する
  - nil 判定、間接参照、空値判定の責務境界を整理し、想定外型の扱いを明示する
  - `skipNil` の意図が伝わる判定フローに整える
  - _Requirements: 3.1, 3.2, 3.3, 3.5_

- [x] 3. 構造体バインド機構をレイヤー非依存で強化する
- [x] 3.1 タグ解釈ルールを堅牢化する
  - タグ指定あり/なしの解釈規約を統一し、誤記時の失敗理由を明確化する
  - source フィールド未存在時の挙動を定義して、静かな失敗を減らす
  - _Requirements: 4.1, 4.2_
- [x] 3.2 constructor 解決と実行の失敗モードを改善する
  - 未登録、型不一致、変換失敗などの失敗分類を整理し、デバッグしやすくする
  - バインド中に発生した検証エラーと実行エラーの返却優先順位を明確化する
  - _Requirements: 4.3, 4.4_
- [x] 3.3 レイヤー非依存の変換利用を前提に契約を整理する
  - 入力元のレイヤーに依存しない命名・解決ルールへ統一する
  - 全フィールド成功時の返却保証と部分成功時の扱いを明確化する
  - _Requirements: 4.5_

- [x] 4. 生成パイプラインの信頼性を高める
- [x] 4.1 (P) コメント解析とオプション解釈の堅牢化
  - 生成コメントの揺れやオプション指定ミスに対する許容範囲を整理する
  - 既定値と明示指定の優先順を固定し、再生成時のぶれを防ぐ
  - _Requirements: 5.1, 5.4_
- [x] 4.2 (P) 走査対象フィルタリングの安全性向上
  - 除外対象ルールを明確化し、不要ファイル混入による誤生成を防ぐ
  - 大規模ディレクトリ走査時の処理安定性を確認する
  - _Requirements: 5.5_
- [x] 4.3 生成結果の決定性を担保する
  - 同一入力から常に同一出力が得られるよう順序と整形を固定する
  - 生成対象なし時の通知内容を一貫化し、利用者が次アクションを判断しやすくする
  - _Requirements: 5.2, 5.3_

- [x] 5. リファクタリング後の品質ゲートを整備する
- [x] 5.1 公開挙動の回帰テストを拡充する
  - 既存の主要ユースケースを基準化し、リファクタリングで外部挙動が崩れないことを確認する
  - エラー集約とバインド失敗のシナリオを重点的に網羅する
  - _Requirements: 1.1, 1.3, 2.1, 3.1, 4.4_
- [x] 5.2 生成フローとバインドフローの統合テストを追加する
  - 生成された登録情報を使った変換シナリオを通しで検証する
  - 失敗系（未登録・不正タグ・検証失敗）を含めて端から端まで確認する
  - _Requirements: 4.3, 4.4, 5.1, 5.2_
- [x]* 5.3 リフレクション処理とエラー収集の性能ベースラインを取得する
  - 高頻度バインド時のレイテンシとメモリ使用量を測定し、改善余地を可視化する
  - 許容閾値を定義し、今後の変更で劣化検知できる形にする
  - _Requirements: 1.1, 4.5_
